# specs — контракт API

TypeSpec-спецификация приложения simple-cal-com: упрощённой версии cal.com, где владелец календаря
ведёт типы событий, а гость без регистрации бронирует свободный слот.

Это единственный источник правды для API. Из `.tsp`-файлов компилятор генерирует
[`../openapi/openapi.yaml`](../openapi/openapi.yaml) — его правит только генератор, руками не трогаем.

## Зачем

- Зафиксировать контракт до написания кода: бэкенд и фронтенд разрабатываются от одной схемы.
- Описать доменную модель и правила в одном месте — они живут в `@doc` рядом с типами.
- Получить машиночитаемый OpenAPI: документация, моки, кодогенерация клиента.

## Структура

| Путь                    | Что внутри                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `main.tsp`              | Точка входа: `@service`, глоссарий доменных сущностей, глобальные правила, сценарии ролей |
| `models/common.tsp`     | Скаляры `Uuid` и `Email`, коды ошибок, форматы ответов 404 / 409 / 422                    |
| `models/owner.tsp`      | `Owner` — владелец календаря, единственный преднастроенный профиль                        |
| `models/event-type.tsp` | `EventType` — шаблон встречи, плюс модели создания и изменения                            |
| `models/slot.tsp`       | `Slot` — вычисляемый свободный интервал, календарь по дням                                |
| `models/booking.tsp`    | `Booking` и `Guest` — занятый интервал и данные записавшегося                             |
| `routes/public.tsp`     | Операции гостя: виды брони, календарь слотов, создание бронирования                       |
| `routes/admin.tsp`      | Операции владельца: CRUD типов событий, список предстоящих встреч                         |
| `tspconfig.yaml`        | Настройки компилятора и эмиттера OpenAPI                                                  |

## Как пользоваться

```bash
npm install       # один раз
npm run build     # скомпилировать спецификацию в ../openapi/openapi.yaml
npm run watch     # то же самое, но пересборка на каждое сохранение
npm run format    # привести .tsp-файлы к единому стилю
```

Проверить сгенерированный OpenAPI линтером — из корня репозитория:

```bash
npx @redocly/cli lint simple-cal-com
```

Порядок работы: правим `.tsp` → `npm run build` → коммитим и исходники, и обновлённый
`openapi.yaml`. Если сборка падает, компилятор указывает файл и строку.

Для подсветки синтаксиса и автодополнения поставь расширение TypeSpec для VS Code.
